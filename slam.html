SLAM Project: Particle Filtering Using Monte Carlo Localization

Spring 2025 16-833 Robot Localization and Mapping Python, Git
Overview

Implemented a Monte Carlo Localization (MCL) system using a recursive Bayesian filter to estimate a robot's global (x, y, θ) pose with no initial knowledge using only odometry, LiDAR scans, and an occupancy grid map.

Monte Carlo Localization

1 · Prediction Step (Motion Model)

  • Updates the predicted particle poses based on the robot's incoming odometry data
  • Accounts for kinematic drift and wheel slip using probabilistic Gaussian noise
  • Vectorized, so all particles update in a single operation

2 · Correction Step (Sensor Model)

  • Simulates LiDAR measurements by casting 90 rays per particle against the known occupancy grid
  • Calculates an observation weight for each particle by comparing expected ranges to actual readings using a probabilistic beam model

3 · Resampling

  • Low-variance resampling algorithm to draw a new particle set proportional to the normalized sensor weights
  • Systematically removes low-probability particles and duplicates accurate ones to drive convergence onto the true pose

↻ Repeated at every sensor update until the particle cloud converges

Implementation & Optimization

Tuning Strategy

  • Sensor Weighting: Heavily weighted Zhit (2.0) to trust LiDAR in closed spaces, kept Zmax low (0.05) due to high wall density, and maintained a high Zrand (100) to prevent premature, incorrect convergence[cite: 10].
  • Raycast Vectorization: Instead of iteratively computing ray intersections, the function generates a grid of potential intersections and evaluates them entirely in parallel[cite: 11, 12].

Adaptive Particle Count (Extra Credit)

Implemented a dynamic decay strategy to shrink the particle set as localization confidence increases, minimizing computational load[cite: 15].

  • Uncertainty Metric (Entropy): Calculates the Shannon entropy of the particle weights to measure distribution uniformity[cite: 15].
  • Spread Metric (Spatial Variance): Evaluates the physical clustering of particles in the state space[cite: 15].
  • Dynamic Decay: The particle count is continuously scaled by max(0.3, s/smax) · max(0.3, σ/σmax) and safely clamped above a minimum threshold[cite: 15].

Challenges & Future Work

Failure Modes

  • Divergence in Open Spaces: Log 4 failed to track, resulting in particles moving through occupied walls[cite: 14]. This is likely due to prolonged exposure to open spaces where the tuned sensor model is less deterministically informative[cite: 14].
  • Symmetric Ambiguity: On logs 2 and 3, early iterations sometimes caused the filter to incorrectly cluster in symmetrical, alternate portions of the map before eventually diverging[cite: 14].

Next Steps

  • Visual Debugging: Overlay the generated ray-cast map directly against the raw LiDAR data logs to visually identify where the sensor model misaligns[cite: 14].
  • Dataset-Specific Tuning: Refine the sensor model parameters to handle the challenging open-space features of logs 2, 3, and 4, rather than relying on a baseline tuned entirely on log 1[cite: 14].
  • Advanced Modeling: Implement a dynamic motion model capable of adapting to varying speeds and explore alternative resampling schemes for harsh environments[cite: 14].
